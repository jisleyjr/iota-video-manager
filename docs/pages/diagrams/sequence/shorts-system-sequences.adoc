= YouTube Shorts and Reels System — Sequence Diagrams

NOTE: This document describes the planned product architecture. The implemented API currently provides only the Spring Boot/MySQL foundation and health endpoints.

These sequences describe the initial system behavior:

* Media arrives through watched folders and browser uploads.
* The system generates complete short-form drafts for creator approval.
* Approved videos are downloaded and manually uploaded to social platforms.
* The Application API discovers public YouTube uploads and refreshes current statistics every six hours by default.
* Direct publishing integrations are a future enhancement.

== Media ingestion, analysis, and cataloging

[mermaid]
----
sequenceDiagram
    autonumber
    actor Creator
    participant Folder as Watched Folder Service
    participant Upload as Upload App
    participant Library as Media Library
    participant AI as GPU Media Intelligence
    participant Catalog as Searchable Catalog

    alt New file in mounted drive/folder
        Folder->>Library: Detect and register video/photo
    else Creator uploads through browser
        Creator->>Upload: Upload media
        Upload->>Library: Store original and metadata
    end

    Library->>AI: Queue media analysis
    AI->>AI: Extract video frames, audio, motion, and scenes
    AI->>AI: Detect action moments, people, vehicles, terrain, and quality
    AI->>AI: Identify photo subjects, setting, and visual matches
    AI->>Catalog: Save clips, timestamps, tags, embeddings, and linked photos
    Catalog-->>Creator: Media becomes searchable and ready for ideas
----

== Short idea and creator approval

[mermaid]
----
sequenceDiagram
    autonumber
    actor Creator
    participant Studio as Shorts Idea App
    participant Catalog as Media Catalog
    participant AI as GPU Creative Service

    Creator->>Studio: Request ideas or choose an adventure/theme
    Studio->>Catalog: Find strong action clips and related photos
    Catalog-->>Studio: Ranked media, metadata, and prior-use history
    Studio->>AI: Create short-form concepts

    loop For each promising concept
        AI->>AI: Select hook, action sequence, photos, captions, and pacing
        AI->>AI: Generate title, description, hashtags, and music suggestion
        AI->>Catalog: Save versioned draft and ordered source references
    end

    Catalog-->>Studio: Present drafts ranked by predicted quality
    Studio-->>Creator: Show idea, storyboard, preview, and rationale

    alt Creator approves
        Creator->>Studio: Approve or request edits
        Studio->>AI: Queue final render
    else Creator rejects
        Creator->>Studio: Reject with optional feedback
        Studio->>AI: Learn preference for future recommendations
    end
----

== Final rendering and manual publishing

[mermaid]
----
sequenceDiagram
    autonumber
    actor Creator
    participant Studio as Review App
    participant Render as GPU Render Worker
    participant Catalog as Media Catalog
    participant Library as Media Library
    participant Output as Finished Shorts Library

    Studio->>Render: Render approved draft
    Render->>Catalog: Load approved draft version and ordered source references
    Catalog-->>Render: Asset IDs, scene time ranges, and transformations
    Render->>Library: Retrieve original clips, photos, and audio
    Render->>Render: Compose 9:16 video, captions, transitions, and soundtrack
    Render->>Render: Validate duration, resolution, audio, and safe framing
    Render->>Output: Store final MP4, thumbnail, and publishing metadata
    Render->>Catalog: Record output, storage references, and render metadata
    Catalog-->>Studio: Notify that final video is ready
    Studio-->>Creator: Preview and download finished short

    opt Creator inspects output sources
        Creator->>Studio: Open finished-video details
        Studio->>Catalog: Request output lineage
        Catalog-->>Studio: Draft version, ordered assets, and source time ranges
        Studio-->>Creator: Show contributing source media and transformations
    end

    Creator->>Creator: Upload manually to YouTube Shorts or Instagram Reels

    Note over Output,Creator: Future integration: connect YouTube/Instagram accounts for direct publishing and scheduling.
----

== Scheduled YouTube discovery and refresh

See xref:api/youtube-monitoring.adoc[YouTube monitoring API] for the configuration, retention, and error handling.

[mermaid]
----
sequenceDiagram
    autonumber
    participant Sync as API YouTube Synchronization
    participant Client as API YouTube Client
    participant YouTube as YouTube Data API v3
    participant Catalog as Media Catalog

    Note over Sync,Catalog: Initial startup and every six hours; skip if another run holds the synchronization lock
    Sync->>Catalog: Acquire synchronization lock
    Sync->>Client: Resolve configured channel uploads playlist
    Client->>YouTube: channels.list(part=contentDetails, id=channelId)
    YouTube-->>Client: Uploads playlist ID
    Client-->>Sync: Uploads playlist ID
    loop Every uploads playlist page
        Sync->>Client: Fetch next page
        Client->>YouTube: playlistItems.list(part=contentDetails, playlistId, pageToken)
        YouTube-->>Client: Video IDs and nextPageToken
        Client-->>Sync: Discovered video IDs and nextPageToken
    end
    Sync->>Catalog: Read stored video IDs for configured channel
    Catalog-->>Sync: Previously imported IDs
    Sync->>Sync: Deduplicate discovered and stored IDs
    loop Batches of up to 50 video IDs
        Sync->>Client: Fetch metadata, status, and current statistics
        Client->>YouTube: videos.list(part=snippet,contentDetails,status,statistics, id=IDs)
        alt Successful lookup
            YouTube-->>Client: Returned video resources
            Client-->>Sync: Returned videos and omitted IDs
            Sync->>Catalog: Upsert eligible public videos and current counts
            Sync->>Catalog: Mark existing omitted or ineligible videos unavailable
            Note over Sync,Catalog: Preserve output associations; unavailable lookups do not advance last_synced_at
        else Request failure
            YouTube-->>Client: Error or timeout
            Client->>Client: Bound transient retries; stop immediately on quota or configuration errors
            Client-->>Sync: Failure after allowed attempts
            Note over Sync,Catalog: Leave affected records unchanged and stop this run
        end
    end
    Sync->>Catalog: Release synchronization lock even on failure
    Note over Sync,Catalog: Independent hourly cleanup and startup cleanup delete records last synchronized at least 30 days ago
----

== Read monitored YouTube videos

[mermaid]
----
sequenceDiagram
    autonumber
    actor Creator
    participant Portal as Creator Portal
    participant Queries as API YouTube Video Queries
    participant Catalog as Media Catalog

    Creator->>Portal: Open YouTube Videos
    Portal->>Queries: GET /api/youtube/videos?page=0&size=25
    Queries->>Catalog: Read configured channel's unexpired videos, newest first
    Catalog-->>Queries: Page of videos and total count
    Queries-->>Portal: Metadata, counts, availability, and refresh times
    Portal-->>Creator: Show uploads and timestamped statistics
    Creator->>Portal: Open a video's details
    Portal->>Queries: GET /api/youtube/videos/{id}
    Queries->>Catalog: Read unexpired video and optional output reference
    Catalog-->>Queries: Video record or no match
    Queries-->>Portal: Video details or 404
    Portal-->>Creator: Show details and existing lineage link, or not found
    Note over Portal,Catalog: Reads use stored records; no YouTube request is made
----
